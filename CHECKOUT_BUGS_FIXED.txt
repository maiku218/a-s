CHECKOUT BUG REPORT - 2026-10-07
================================

SUMMARY
-------
Tested the complete checkout flow (sale, receipt, void, refund) and found 2 bugs
that were blocking the checkout process. Both are now fixed.

BUG 1: Force-Password-Change Blocks Admin POST Mutations
---------------------------------------------------------
SEVERITY: HIGH (prevents admin from doing their job)

PROBLEM:
- Admin account had `force_password_change=1` in database (from initial setup)
- The `admin_required` decorator blocked ALL routes when this flag was set
- Admin couldn't register cashiers, do stock_in, or any other admin action
- Even POST mutations (register_cashier, stock_in, etc.) were blocked

ROOT CAUSE:
In `app.py` lines 541-550, the `admin_required` decorator:
```python
if session.get('force_password_change') and f.__name__ != 'force_password_change':
    return redirect(url_for('force_password_change'))
```
This blocked ALL routes including POST mutations.

FIX:
Modified `admin_required` to:
1. Allow POST mutations (so admin can do their job)
2. Allow GET /admin (dashboard) as natural landing page after mutations
3. Only block GET navigation to other pages

```python
if session.get('force_password_change'):
    if request.method == 'GET' and f.__name__ not in ('force_password_change', 'admin_dashboard'):
        return redirect(url_for('force_password_change'))
```

Also updated all admin POST routes (register_cashier, stock_in, etc.) to redirect
to `admin_dashboard` instead of back to the form page, so the POST->GET redirect
lands on an allowed page.

FILES CHANGED:
- app.py: admin_required decorator (lines 541-558)
- app.py: register_cashier validation error redirects (lines 2555, 2561)
- app.py: register_cashier success redirect (line 2590)

BUG 2: CSRF Token Fetch Blocked by Force-Password-Change
-----------------------------------------------------------
SEVERITY: MEDIUM (affects automated testing, not manual use)

PROBLEM:
- Test scripts fetch CSRF token via GET to /admin_login
- That GET was blocked by force_password_change redirect
- Token from force_password_change page worked but caused confusion

NOTES:
- This doesn't affect manual users (they see the force_password_change page
  and change their password, then can access everything)
- Only affects automated scripts that fetch tokens programmatically
- The token from force_password_change page is valid for the session
