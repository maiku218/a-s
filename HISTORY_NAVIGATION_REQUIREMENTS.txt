OVERVIEW
--------
Create a "History" navigation section that records ALL ADMIN ACTIVITIES.
Every action performed by the admin is logged and displayed in the
History page. Cashier transactions (sales, voids, refunds) are also
reflected in the history as they affect stock levels.


================================================================================
1. HISTORY NAVIGATION ACCESS
================================================================================

1.1 Navigation Location
- Add a "History" item in the ADMIN sidebar
- This is primarily an ADMIN feature - all admin activities are recorded here
- Cashier can also view History (their own transactions: sales, voids, refunds)

1.2 Route
- Admin: /admin/history
- Cashier: /cashier/history (cashier's own transaction history)


================================================================================
2. ALL ADMIN ACTIVITIES RECORDED IN HISTORY
================================================================================

EVERYTHING the admin does gets logged in History. This includes but is NOT
limited to:

  - Login / Logout
  - Add Product (e.g., adding 10 Chocomucho)
  - Edit Product (name, price, stock, category changes)
  - Delete Product
  - Register Cashier
  - Delete Cashier
  - Edit Cashier (status, name, password changes)
  - Change Admin Password
  - Receipt Customization changes
  - Database Backup / Restore
  - Any other admin panel actions

Each admin activity creates a history entry showing:
  - What action was performed
  - Who performed it (admin username)
  - When it was performed (date/time)
  - Details (e.g., "added 10 Chocomucho", "edited product: Chocomucho")


================================================================================
3. DATA SOURCE - stock_movements TABLE
================================================================================

The stock_movements table is the PRIMARY source for History entries.
It captures all stock-level changes (IN and OUT movements).

Table: stock_movements (EXISTING in database_sqlite.py lines 91-99)
  - id              INTEGER PRIMARY KEY AUTOINCREMENT
  - product_id      INTEGER NOT NULL (FK -> products.id)
  - movement_type   VARCHAR(10) NOT NULL  -- 'IN' or 'OUT'
  - quantity        INTEGER NOT NULL
  - reason          VARCHAR(100)          -- e.g., 'Stock Addition', 'Sale', 'Void Sale'
  - movement_date   TEXT DEFAULT (datetime('now', 'localtime'))

Also uses admin_activity table for non-stock admin actions
(e.g., login, logout, delete product, register cashier, etc.)

Table: products (for product name lookup)
  - id, product_name, barcode, price, stock, etc.


================================================================================
4. HISTORY ENTRY TYPES
================================================================================

Every history entry contains:
  - Product Name (e.g., "Chocomucho")
  - Action Type (Add, Edit, Delete, Stock Change, Sale, Void, Refund, etc.)
  - Quantity (+ for IN, - for OUT)
  - Date/Time (timestamp)
  - Reason (e.g., "Stock Addition", "Sale", "void", "edit product")
  - Actor (username)
  - Role (admin or cashier)

4.1 ADMIN ACTIVITIES (recorded in BOTH admin_activity AND stock_movements)

  Type: LOGIN
    Logged in admin_activity: action = 'Admin Login'
    History shows: "Admin [username] logged in"
    Date: login time
    Reason: "admin login"

  Type: LOGOUT
    Logged in admin_activity: action = 'Admin Logout'
    History shows: "Admin [username] logged out"
    Date: logout time
    Reason: "admin logout"

  Type: ADD PRODUCT / STOCK ADDITION
    Example: Admin adds 10 Chocomucho
    History shows: "Admin [username] added 10 Chocomucho"
    Stock Movement: movement_type = 'IN', quantity = 10, reason = 'Stock Addition'
    Display: "+10 Chocomucho" (green, IN-bound)
    Date: datetime of the action
    Actor: Admin username
    Reason: "Stock Addition"
    Direction: IN (stock went in)

  Type: EDIT PRODUCT - Change Quantity
    Admin changes product quantity (e.g., from 510 to 10)
    History shows: "-500 Chocomucho" | Reason: Change Quantity
    Stock Movement: movement_type based on delta, quantity = |delta|

  Type: DELETE PRODUCT
    Logged in admin_activity: action = 'Delete Product'
    Stock Movement: movement_type = 'OUT', quantity = remaining stock, reason = 'Product Deleted'
    History shows: "Admin [username] deleted product: Chocomucho"
    Date: datetime of deletion
    Actor: Admin username
    Reason: "delete product"
    Direction: OUT (stock removed permanently)

  Type: REGISTER CASHIER
    Logged in admin_activity: action = 'Register Cashier'
    History shows: "Admin [username] registered cashier: [cashier_username]"
    Date: datetime of registration
    Actor: Admin username
    Reason: "register cashier"

  Type: DELETE CASHIER
    Logged in admin_activity: action = 'Delete Cashier'
    History shows: "Admin [username] deleted cashier: [cashier_username]"
    Date: datetime of deletion
    Actor: Admin username
    Reason: "delete cashier"

  Type: EDIT CASHIER
    Logged in admin_activity: action = 'Update Cashier'
    History shows: "Admin [username] updated cashier: [cashier_username]"
    Date: datetime of update
    Actor: Admin username
    Reason: "update cashier"

  Type: CHANGE PASSWORD (ADMIN)
    Logged in admin_activity: action = 'Change Password'
    History shows: "Admin [username] changed password"
    Date: datetime of password change
    Actor: Admin username
    Reason: "change password"

4.2 CASHIER TRANSACTIONS (recorded in stock_movements)

  Type: SUCCESSFUL SALE (STOCK OUT)
    When: After successful checkout/payment
    Stock Movement: movement_type = 'OUT', quantity = [items purchased], reason = 'Sale'
    Example: Cashier sells 2 Chocomucho
    History shows: "-2 Chocomucho" (red, OUT-bound)
    Date: datetime of sale
    Actor: Cashier username
    Reason: "Sale"
    Direction: OUT (stock went out)

  Type: VOID TRANSACTION
    When: Cashier voids a completed sale (via /api/void_sale)
    What happens:
      1. Sale status changed to 'Voided' in sales table
      2. Stock reversed: products get stock BACK (e.g., +2 Chocomucho)
      3. stock_movement entry: movement_type = 'IN', quantity = [reversed], reason = 'Void Sale'
    History shows: "+2 Chocomucho" (green, IN-bound) with "VOID" badge
    Full entry: "VOID - +2 Chocomucho | Reason: [cashier's reason]"
    Date: datetime of void action
    Actor: Cashier username
    Reason: [the void reason entered by cashier]
    Direction: IN (stock restored)
    Special: Red/Orange "VOID" badge displayed prominently

  Type: REFUND TRANSACTION
    When: Cashier refunds a completed sale (via /api/refund_sale)
    What happens:
      1. Sale status changed to 'Refunded' in sales table
      2. Stock reversed: products get stock BACK
      3. stock_movement entry: movement_type = 'IN', quantity = [reversed], reason = 'Refund Sale'
    History shows: "+2 Chocomucho" (green, IN-bound) with "REFUND" badge
    Full entry: "REFUND - +2 Chocomucho | Reason: [cashier's reason]"
    Date: datetime of refund action
    Actor: Cashier username
    Reason: [the refund reason entered by cashier]
    Direction: IN (stock restored)

7. VOID TRANSACTION SPECIFIC REQUIREMENTS
================================================================================

7.1 Void Flow in Cashier
1. Cashier completes a sale
2. Later, clicks "Void" button on the transaction in cashier_history.html
3. Prompt appears: "Enter void reason:" (REQUIRED - cannot be empty)
4. Cashier enters reason (e.g., "wrong item", "customer complaint")
5. System processes:
   a. Sale status -> 'Voided' in sales table
   b. Stock reversed: +[quantity] back to each product
   c. stock_movement: movement_type='IN', reason='Void Sale', quantity=[reversed]
   d. History entry created with "VOID" badge

7.2 Display in History (Void)
"VOID - +2 Chocomucho | Date: 2026-09-19 14:05:00 | Reason: wrong item | Actor: cashier_mike"
[VOID badge in red/orange, prominently displayed]

7.3 Void Stock Reversal Details
- When voiding sale of 2 Chocomucho, stock goes BACK by 2
- Logged as IN movement in stock_movements
- History shows: "+2 Chocomucho" (green, with VOID badge)
- Reason field: "void" or the specific cashier reason
- This is a reversal - it UNDOES the original sale's stock deduction

7.4 Admin Views Void in History
- Admin sees voided transactions in /admin/history
- Can see: who voided, when, what was voided, the reason
- Void entries clearly marked with VOID badge

9.3 Edit Product - Add Stock Movement Logging
In app.py edit_product route (~line 979), ADD after UPDATE:
  BEFORE UPDATE:
    cur.execute("SELECT stock FROM products WHERE id=?", (id,))
    old_stock = cur.fetchone()[0]
  AFTER UPDATE (new stock is already saved):
    stock_delta = new_stock_value - old_stock
    if stock_delta != 0:
        movement_type = 'IN' if stock_delta > 0 else 'OUT'
        cur.execute("""
            INSERT INTO stock_movements (product_id, movement_type, quantity, reason)
            VALUES (?, ?, ?, 'Change Quantity')
        """, (id, movement_type, abs(stock_delta)))

9.4 Delete Product - Log Stock OUT Before Deleting
In app.py delete_product (~line 925), CHANGE from:
  cur.execute("DELETE FROM stock_movements WHERE product_id=?")
TO:
  # First, log what was removed
  cur.execute("SELECT stock FROM products WHERE id=?", (id,))
  final_stock = cur.fetchone()[0]
  if final_stock > 0:
      cur.execute("""
          INSERT INTO stock_movements (product_id, movement_type, quantity, reason)
          VALUES (?, 'OUT', ?, 'Product Deleted')
      """, (id, final_stock))
  # Then proceed with existing deletion logic
  cur.execute("DELETE FROM stock_movements WHERE product_id=?", (id,))
  cur.execute("DELETE FROM sale_items WHERE product_id=?", (id,))
  cur.execute("DELETE FROM products WHERE id=?", (id,))

11.1 Admin adds 10 Chocomucho

  5. Live update: If cashier is viewing history, this entry appears within 5 seconds

11.2 Admin edits Chocomucho (changes quantity from 510 to 10)
  1. Admin edits product, changes stock from 510 to 10
  2. Stock delta: 10 - 510 = -500
  3. stock_movements: (product_id, 'OUT', 500, 'Change Quantity', datetime_now)
